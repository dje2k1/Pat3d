# Kit Rush 3D v3 — port to three.js r186 (WebGPU + TSL) and art upgrade

The user (French, plays on PC and phone) asked: "use recent three.js on GitHub, and improve the textures and the
rendering of Kit, the scenery and the cars". v2 (three.js r128, WebGL 1-style shader hacks) is live on GitHub Pages
from this repo. v3 replaces it with a three.js r186 `WebGPURenderer` build (WebGPU when the browser has it, the
renderer's own WebGL 2 backend otherwise), a TSL node-based "Unreal-like" post stack, real PBR textures generated by
our own scripts, and much better looking models and materials. The gameplay must not change.

Read SPEC.md (base game contract) and SPEC2.md (v2: post, VFX, Act 2 city/board/flight) first: every gameplay
contract, module API and test in them still holds unless this file changes it.

## 2. Renderer

- `K.view.renderer = new THREE.WebGPURenderer({ canvas, antialias: false, powerPreference: 'high-performance' })`;
  `await renderer.init()` before the first frame (boot becomes async; the title screen may show "Chargement…").
  `?gl` in the URL forces the WebGL 2 backend (`forceWebGL: true`). `K.view.backend` = `'webgpu' | 'webgl2'`,
  shown in the pause menu ("Rendu : WebGPU" / "Rendu : WebGL 2"). If init fails: French error screen with a link to
  `legacy/`.
- The game keeps driving frames with `requestAnimationFrame` (tests replace it with a deterministic shim) and calls
  `renderer.render(...)` / the render pipeline synchronously after init. Precompile with `renderer.compileAsync`
  behind the loading card where it helps (city, boss).
- No GLSL anywhere: no `onBeforeCompile`, no `ShaderMaterial`/`RawShaderMaterial`, no `EffectComposer`. All custom
  shading is TSL (`three/tsl`: `Fn`, `uniform`, `attribute`, `texture`, `instancedArray`, `mx_noise_*`, `mx_worley_*`,
  `If/select`, …) on node materials (`MeshStandardNodeMaterial`, `MeshPhysicalNodeMaterial`, `MeshSSSNodeMaterial`,
  `SpriteNodeMaterial`, `MeshBasicNodeMaterial`, …).
- Colour management: linear workflow, sRGB output, albedo textures `SRGBColorSpace`, data textures `NoColorSpace`.
  Physically based light units (r155+): re-balance sun / hemisphere / point light intensities so the look is at
  least as good as v2 (golden-hour city, bright tropical island).
- Shadows: `CSMShadowNode` (addons/csm) on Ultra/Élevé for the sun, a single shadow map on Moyen, cheap or none on
  Économie. Soft shadows (PCF soft / VSM). Kit and cars must cast clean contact shadows.
- Environment: a procedural sky (`SkyMesh` or our own TSL sky) feeding `scene.environment` (PMREM) per act so PBR
  metals, car paint, glass and rings reflect the right sky.

## 3. Post pipeline ("Unreal-like", K.post)

Keep the K.post API other modules use (SPEC2: `speed()`, `flash()`, `cinematic()`, `letterbox`, `setQuality()`,
`setSR()`, `quality`, persistence, pause-menu rows) — extend it, don't break callers. Built with `THREE.RenderPipeline`
(r183+ name of PostProcessing) and the TSL display nodes in `addons/tsl/display/`:

- scene `pass()` with MRT (colour, normals, velocity, depth as needed);
- `GTAONode` ambient occlusion; `SSGINode` screen-space GI on Ultra; `SSRNode` reflections (water, wet asphalt,
  car paint, glass) on Ultra/Élevé;
- `BloomNode` (HDR), `GodraysNode` + `LensflareNode` for the sun where it is on screen, `DepthOfFieldNode` in
  cinematics (bumper orbit, results), `MotionBlur` at high speed;
- temporal AA: `TRAANode`; **Super Résolution** = render at a lower internal resolution and upscale with `TAAUNode`
  (temporal, the DLSS-like path) or `FSR1Node` + `SharpenNode` (spatial fallback);
- tone mapping (AgX or ACES) + our grade (warm/cool split, saturation), vignette, light film grain, subtle chromatic
  aberration, letterbox, flash, speed streaks.

Presets (persisted, pause menu): **Ultra** (all of the above, native res + TRAA, SSGI, fur shells 16, grass blades
dense, 2K hero textures), **Élevé** (desktop default: GTAO, SSR, bloom, godrays, DOF, TRAA or 0.85×TAAU),
**Moyen** (phone default: 0.6× internal res + TAAU or FSR1, GTAO half-res, bloom, no SSR/SSGI, fur shells 6,
fewer grass blades), **Économie** (0.75× + FXAA, bloom-lite only, no AO/SSR, 1K/half textures, no fur shells).
`K.gfx` (owned by K.post) exposes the active preset's content knobs to other modules:
`{ preset, furShells, grass, texRes: 'full'|'half', shadows, ssr }` plus an `onChange(fn)` hook, so world/kit/city
code can rebuild what depends on the preset.

## 4. Textures (K.tex) and asset generation

- `tools/tex/texlib.py` (foundation): seamless value/gradient/worley noise, fbm, domain warp, height->normal (tangent
  space, OpenGL convention +Y), ORM packing (R = AO, G = roughness, B = metalness), WebP writer, `full` (1024 or 2048)
  and `half` variants, a manifest `assets/manifest.json` (name -> files, size, colour space).
- Each art role owns `tools/tex/<role>_*.py` and `assets/tex/<role>/`. Albedo, normal, ORM per material; tiling where
  it makes sense. Budgets: whole `assets/` ≤ 40 MB on disk; Act 1 initial download ≤ 15 MB; Act 2 extra ≤ 15 MB;
  GPU texture memory (estimated from loaded textures incl. mips) ≤ 220 MB Ultra, ≤ 90 MB Moyen (`half` set).
- `K.tex` (foundation, `src/10-core.js` or a new `src/12-tex.js`): `load(name, opts)` -> `THREE.Texture` (cached,
  correct colour space, wrap, anisotropy, returns a neutral 1×1 fallback immediately and fills in when loaded),
  `preload(names, onProgress) -> Promise`, `set` (`'full'|'half'` from K.gfx), `stats()` (count, estimated bytes).

## 5. Art direction

Stylised but rich, like a current AAA 3D platformer: PBR materials with visible micro-detail at close range, soft
bounce-like lighting, contact shadows and AO, crisp reflections, saturated but natural colours, cinematic grade.
Original characters and places only (no names, logos or likenesses from other games or brands).

- **Kit** (fox hero, `30-player.js` look + `35-board.js` board): smoother, higher-quality body (subdivided/sculpted
  shapes, no visible facets at play distance), real fur: shell fur (instanced shells with a fur-density texture,
  wind/motion lag, count from K.gfx) + fur normal/albedo, fluffy tail and cheek tufts, white chest/tail tip;
  expressive eyes (iris texture, cornea highlight, eyelids that blink), glossy nose, outfit (scarf/gloves/shoes) with
  fabric textures; subsurface-ish wrap lighting (`MeshSSSNodeMaterial` or TSL) and rim light. Same silhouette,
  palette, scale, pivot and every existing pose/animation (run, ball/spin, homing, skate, flight).
  Skateboard: wood deck with grip tape and graphics, metal trucks, urethane wheels.
- **Vehicles** (`26-vehicles.js`, extracted from 25-city.js by the foundation): real car shapes (rounded body, wheel
  arches, bumpers, separate glass), detailed wheels (tyre tread + rims), chrome trims, emissive head/tail lights
  that bloom, plates; clearcoat metallic paint with flake normal (`MeshPhysicalNodeMaterial`), per-instance paint
  colour; taxis, vans, delivery vans, buses, cable car, tram and the road-works barriers all upgraded. Keep
  instancing, LOD (detailed near / simple far) and **exactly the same `VT` half extents, `vehicleTop()` and
  collision boxes** (physics and tests depend on them).
- **Act 1 scenery** (`20-world.js`): PBR grass with instanced grass blades near the camera (wind, LOD, preset
  density), the checkered cliffs kept as the level's identity but made of real rock/soil materials with normal
  detail, dirt path, beach sand, water (TSL: reflections/SSR, depth colour, foam, caustics), palms (bark, leaves with
  translucency), flowers, rocks, sky with clouds, loops/ramps/bridges with proper materials.
- **Act 2 scenery** (`25-city.js`): Victorian houses with wood siding, trims, shingles, window glass with fake
  interiors (interior mapping), streets with asphalt (cracks, patches, worn paint lines, manholes, wet puddles that
  reflect via SSR), concrete sidewalks and curbs, street furniture, trees, the red suspension bridge, bay water,
  golden-hour sky.
- **Entities** (`40-entities.js`): polished gold rings, robot enemies in painted metal with emissive eyes, chrome
  springs/bumpers, monitors with glowing screens, the boss machine (metal panels, rivets, glass dome), star posts,

- **VFX** (`16-vfx.js`): same K.vfx API, TSL particles (instanced sprites, additive HDR so they bloom).

### K.view (10-core.js)
- `await K.view.init()` → `true` | `false` (`view.error` in French). Creates `THREE.WebGPURenderer({ canvas: #gl,
  antialias: false, powerPreference: 'high-performance', forceWebGL: ?gl })` and awaits `renderer.init()`; without
  WebGPU three falls back to its WebGL 2 backend by itself. `K.view.backend` = `'webgpu' | 'webgl2'`, `forceGL`,
  `initMs`. Renderer: `shadowMap.enabled`, `PCFShadowMap` (PCFSoftShadowMap is removed in r186), sRGB output, ACES.
- Boot is async (90-main.js `bootAsync`): loading screen with a progress bar ("Chargement…") while the renderer
  starts, `K.tex.init()` + `K.tex.preloadGroup('act1')` run, the island is built, then `renderer.compileAsync(scene,
  camera)`; `K.game.booted = true` at the end (tests wait for it). Act 2: the city is built at once on the loading
  card, its `act2` textures and `compileAsync` run in the background and the card waits for both (at most 4 s).
- Frame: main calls `K.view.beginFrame()`, `K.post.render()` (or `renderer.render`), `K.view.endFrame()`.
  `K.view.stats` = `{ calls, tris }` (whole frame incl. post passes) and `{ sceneCalls, sceneTris }` (renders of
  `K.view.scene`: scene pass + shadow maps — the SPEC3 §6 budget numbers). r186 only resets `renderer.info` inside its
  own animation loop: never read `renderer.info.render.calls` directly.
- `K.view.showFatal(msg)` shows the French DOM overlay (with the `legacy/` link). GPU device / context loss →
  `view.lost = true` + overlay ("Recharge la page").
- `K.tsl` — shared TSL functions (each emitted once per shader): `hash21(vec2)`, `vnoise(vec2)` (0..1 value noise),
  `fbm(vec2)` (4 octaves), `checker(p, w)` (box-filtered 0..1), `fw(p)` (pixel footprint, `max(|dFdx|,|dFdy|)`).
- `K.util.spinY(geometry, angle)` — rotates a (shared, instanced) geometry about its local Y in place (see gotchas).

### K.post + K.gfx (15-post.js — placeholder, owner: post)
- `THREE.RenderPipeline` with `pass(scene, camera)` → bloom (`BloomNode`, not on Économie) → the v2 grade written in
  TSL with `outputColorTransform = false` (ACES filmic × exposure 1.04, warm-highlight / cool-shadow tint,
  saturation 1.12, vignette, sRGB OETF, S-curve 0.2) → flash and letterbox. Super Résolution = `scenePass.setResolutionScale(sr)`
  (bilinear upscale for now). `K.post.uHDR` is a TSL `uniform` (1 while the pipeline runs): world/city sky shaders use
  it directly. `?nopost` → `K.post.ok = false`, direct rendering.
- API kept and callable: `init, ok, render(dt), setQuality(q), quality, setSuperRes(on), superRes, cinematic(on, opts),
  speed(v), flash(color, s), setSun(dir, hex), refreshEnvironment(pos, {floor, floorOpacity, floorColor, intensity}),
  stats(), envMap, letterbox (current bar height 0..0.5)`. `speed()`/`cinematic()` only track their values (stats().speed,
  .cinematic) — the effects (motion blur, DOF, CA, grade, vignette, grain, godrays, lens flare) are the post builder's.
- `refreshEnvironment` renders a `THREE.CubeCamera` into one reused `CubeRenderTarget` (half float, 128 / 64 px phone,
  translucent floor under the vantage point, `userData.noEnv` objects hidden) and sets `scene.environment` to it — the
  node materials' PMREMNode prefilters it (again after each capture); `intensity` → `scene.environmentIntensity`.
- `K.gfx = { preset, furShells, grass, texRes, shadows, ssr, presets, onChange(fn), offChange(fn), sync() }`, preset
  table: Ultra `{furShells 16, grass 1, texRes 'full', shadows 'csm', ssr true, sr 0.77}`, Élevé `{10, 0.7, 'full',
  'csm', true, sr 0.85}`, Moyen `{6, 0.4, 'half', 'single', false, sr 0.6}`, Économie `{0, 0, 'half', 'cheap', false,
  sr 0.75}`. `grass` is a density factor (0 = no blades), `shadows` one of 'csm' | 'single' | 'cheap'. `onChange(fn)`
  calls `fn(gfx, previousPreset)` after a preset change (rebuild fur shells, grass, shadow setup there). Defaults:
  'high' desktop, 'medium' touch; persisted in K.store 'gfx' / 'superres' as in v2.

### K.tex (12-tex.js) and tools/tex/texlib.py
- Per-role manifests `assets/tex/<role>/manifest.json` (roles: foundation, post, kit, world, city, vehicles,
  entities — all exist, empty; keep yours valid JSON). Runtime name = `'<role>/<texture>'`.
- `K.tex.load(name, { repeat, wrap: 'repeat'|'clamp'|'mirror', anisotropy (8), colorSpace: 'srgb'|'linear',
  fallback: [r,g,b,a] })` → a `THREE.Texture` at once (1×1 neutral image: albedo grey, normal flat, ORM (1, 0.8, 0)),
  the WebP replaces its image in place when it arrives (no material rebuild). sRGB entries get `SRGBColorSpace`, data
  `NoColorSpace`. Images are decoded with `createImageBitmap(…, { imageOrientation: 'flipY' })` and `flipY = false`
  (same UV orientation as a standard three texture on both backends).
- `K.tex.preload(names, onProgress)`, `K.tex.preloadGroup('act1'|'act2'|'common', onProgress)` (boot preloads `act1`
  with the progress bar, Act 2's loading card `act2`), `K.tex.group(g)`, `K.tex.has(name)`, `K.tex.set('full'|'half')`
  (follows `K.gfx.texRes`; loaded textures are re-fetched in place), `K.tex.stats()` → `{ count, loaded, failed,
  pending, res, gpuBytes (w·h·4·4/3 per loaded texture), fileBytes, names }`.
- `tools/tex/texlib.py` (numpy + Pillow, everything tiles): `value_noise, gradient_noise, worley (F1, F2, cell id),
  fbm, ridged, domain_warp, blur, sample_wrap, remap, smoothstep, colorize(t, [(pos, '#hex'), …]),
  srgb_to_linear / linear_to_srgb, height_to_normal(h, strength)` (tangent space, OpenGL +Y), `cavity_ao, orm(ao, rough,
  metal)` (R = AO, G = roughness, B = metalness), `write_webp`, and `Manifest(role)`: `m.add(name, img,
  colorspace='srgb'|'linear', group='act1'|'act2'|'common'|'none', wrap)` writes `<name>.webp` + `<name>_half.webp`
  and the entry `{full, half, size, halfSize, colorSpace, bytes, halfBytes, group, wrap}`; `m.save()` merges into
  your manifest. Example: `tools/tex/foundation_sample.py` (a 256 px cobble set, group 'none', used by the tests).
  Your scripts: `tools/tex/<role>_*.py`, output `assets/tex/<role>/`. Budgets (tested): assets/ ≤ 40 MB, Act 1
  (act1 + common) ≤ 15 MB, Act 2 ≤ 15 MB (manifest `bytes`, full set).

### Tests (test/e2e.js)
- `./build.sh && node test/e2e.js` — every suite on the WebGL 2 backend (`test.html?gl`), Chromium + SwiftShader.
  `--only=` any of `desktop,valley,boss` (the Act 1 desktop run), `v3` (backend + fallback, K.tex sample, assets budget,
  no GLSL, perf budgets per preset, legacy page), `act2, post, fullrun, regress, present, regress2, phone`.
  `node test/e2e.js --webgpu` = WebGPU suite (boot, Act 1 sample, Act 2 sample, presets, no errors; SwiftShader Vulkan:
  the first boot compiles every pipeline on the CPU, several minutes).
- Typical durations on this sandbox (4 shared CPUs, SwiftShader): desktop,valley,boss ≈ 95 s; v3 ≈ 115 s;
  act2,post,regress,present,regress2,phone ≈ 400 s; fullrun ≈ 30 s; whole default run ≈ 11 min; `--webgpu` ≈ 45 s.
  SwiftShader caches compiled shaders: the first boot after a shader change takes 40 s (WebGL 2) to 3 min (WebGPU),
  later boots 5–10 s. Foundation baseline: 80/80 checks + 1 builder target pending (WebGL 2), 6/6 (WebGPU).
- `test/serve.js` serves the repo on 127.0.0.1 (port 0 = free port; `node test/serve.js 8080` by hand).
- Builder targets that depend on your work are reported with `pending('<role>', name, met, notes)`: PEND lines never
  fail the run; turn yours into `check()` when you deliver (e.g. the Moyen draw-call budget).
- In-page helpers (test/page-helpers.js): `T.ticks(n)`, `T.frame()` (one tick + a drawn frame), `T.renderNow()` (draw
  without ticking), `T.pixels()` / `T.pixelsGL()` (canvas pixels via a 2D canvas copy, top-first / bottom-first),
  `T.glStats()` (mean/std/colours + draw calls), `T.drawStats()`, `T.mem()` (renderer.info.memory: geo/tex/programs),
  `T.sync()`. `dev/foundation/run.js --eval="…" --shot=…png [--webgpu] [--phone] [--q=?gl&nopost]` runs a snippet in a
  booted test page (handy for probes and screenshots).

### r186 / TSL gotchas we hit
1. Import map values must start with `./` (a bare `lib/three/…` value is ignored).
2. Colour management is on: `new THREE.Color('#hex')` converts sRGB → linear (v2's `lin()` = `.convertSRGBToLinear()`
   would now double-convert; `lin` is now just `new THREE.Color(hex)`). Vertex colours / instance colours are taken
   as linear. CanvasTextures with colours: `colorSpace = THREE.SRGBColorSpace`; data: `NoColorSpace`.
3. Physically based light units: r128 multiplied punctual and hemisphere lights by π in its shaders → v2 intensities × π.
4. **Instancing runs before `positionNode`**: in an InstancedMesh's `positionNode`, `positionLocal` is already
   instance-transformed (`positionGeometry` is the raw attribute). Per-instance local animation: phase from
   `instanceIndex`, a spin of the shared geometry on the CPU (`K.util.spinY`), or your own instanced attributes.
5. Instance colour multiplies the diffuse of every vertex; read it as `varyingProperty('vec3', 'vInstanceColor')`.
6. `THREE.Points` are 1 px in WebGPU: use `THREE.Sprite(spriteNodeMaterial)` with `sprite.count = n`,
   `positionNode = instancedBufferAttribute(attr)`, `scaleNode`, `rotationNode` (world-unit sizes), or a quad
   InstancedBufferGeometry + `vertexNode` (16-vfx.js).
7. **TSL `Fn` + `If`: any value used by more than one branch must be `.toVar()`'d before the `If` chain** — otherwise
   it is emitted inside the first branch that uses it and read uninitialised in the others (it hid the VFX rings).
   `.assign()` / `.addAssign()` only inside `Fn()`; outside, write pure expressions. Avoid swizzle assignment
   (`v.x.addAssign`): rebuild the vector.
8. Derivatives (`dFdx`, `fw`) and `texture()` with implicit LOD need uniform control flow in WGSL: compute them before
   `If` branches (`select()` is fine, it evaluates both sides).
9. `vertexNode` = clip-space output (sky dome at the far plane: `vec4(clip.xy, clip.w.mul(0.99999), clip.w)`);
   `fragmentNode` replaces the whole fragment output (no fog / tone mapping): used for premultiplied VFX.
10. `BufferAttribute.updateRange` is gone: `clearUpdateRanges()` + `addUpdateRange(start, count)`.
11. `renderer.compile` is gone: `await renderer.compileAsync(scene, camera)`.
12. `scene.environment` = a CubeRenderTarget texture is PMREM-filtered by the node system (CubeCamera flags it after
    each update); scale with `scene.environmentIntensity`. Classic `envMap` on a material still works.
13. Nested renders of the same scene (shadow maps inside the scene pass) — count the outermost only (K.view does).
14. No `gl.readPixels` on WebGPU: draw the canvas into a 2D canvas in the same task (T.pixels) — works on both backends.
15. Headless noise to expect (warnings, not errors): WebGL backend "GL Driver Message … Running out of reserved
    outsideRenderPass queueSerial", WebGPU "Draw with an index count of 0 is unusual".
16. The shader of a material: `await renderer.debug.getShaderAsync(scene, camera, mesh)` → `{ vertexShader,
    fragmentShader }` (GLSL on the WebGL backend, WGSL on WebGPU): the fastest way to debug TSL.
